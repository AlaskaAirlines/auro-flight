# AB#1499242

## Executive Summary

This change makes flight cards in the Alaska Airlines design system readable by screen readers for the first time. Previously, users relying on VoiceOver, TalkBack, NVDA, or JAWS could reach a flight card but heard it broken into 10 or more disconnected fragments — departure city, time, arrival city, and so on — with no coherent sentence tying them together. Now the card announces a single, complete sentence on entry: flight number, departure and arrival stations, times, stop or layover details, reroute information if applicable, cancellation status, and duration. Airlines and partners can localize this announcement using new `i18n-*` attributes without changing any code. The change also migrates the time display component to its latest version, fixing a regression where dates were showing instead of times.

## The Problem

Customers who are blind or have low vision use screen readers to navigate flight listings. The `auro-flight` card — which shows flight number, departure and arrival cities, times, and stop information — gave screen readers no structured entry point. There was no summary spoken when a user landed on a card; instead the reader traversed each visual element individually, announcing station codes and times out of context. Users had no way to quickly understand what flight a card represented without navigating inside it element by element.

A secondary issue was discovered during testing: iOS VoiceOver's swipe-right navigation skipped `auro-flight` cards entirely, meaning iPhone users couldn't reach them at all.

A third issue was discovered post-merge: the `auro-datetime` v5 upgrade changed its API, causing departure and arrival times to display as full dates instead of times only.

---

## Root Cause

Three issues in total:

**1. No coherent SR entry point.** `<section part="flightContainer">` in `src/auro-flight.js` had no `aria-label`. Screen readers entered the card and read its visual children one by one with no sentence framing any of it.

**2. Shadow DOM `aria-hidden` does not reliably hide slotted content.** `aria-hidden="true"` on the `.slotContainer` div inside `auro-flight-main`'s shadow DOM hid contents in Chrome but slotted light DOM children (`auro-flightline`) are not guaranteed hidden by a shadow-ancestor's `aria-hidden` across all browsers and AT.

**3. iOS VoiceOver skips elements with no accessible text node.** VoiceOver's swipe navigation requires a concrete readable text node — an `aria-label` attribute alone on a shadow DOM element is insufficient. When all shadow DOM children are `aria-hidden`, VoiceOver finds nothing to land on and skips the element entirely.

**4. `auro-datetime` v5 breaking changes.** The `setDate` attribute was renamed to `value`, and `type="tzTime"` was renamed to `type="time"`. The component version in `datetimeVersion.js` was still set to `4.0.0`, causing version mismatch behavior.

---

## The Fix

**Screen reader announcement** — A visually-hidden `<span role="text" class="sr-label" aria-label="${label}">&#8203;</span>` is rendered as the first child of the shadow DOM `<section>` in `src/auro-flight.js`. The `_buildAriaLabel()` method assembles the full announcement:

- Flight number (letter-spaced for correct AT pronunciation) or `"Multiple flights"`
- Departure sentence via `i18nDeparture` template
- Arrival sentence via `i18nArrival` template
- Day-change suffix (`"next day"` / `"N days later"`)
- Stop and layover details with "and" conjunctions before the last entry
- Reroute announcement when rerouted stations are set
- Nonstop label or cancellation status
- Duration

The `&#8203;` (zero-width space) gives Safari/VoiceOver a non-empty text node to anchor to without producing any spoken output. `role="text"` tells VoiceOver to read the `aria-label` value directly, bypassing text content — this prevents VoiceOver from pronouncing punctuation characters (e.g. `.` → "full stop"). The `.sr-label` CSS uses `width: 100%; height: 100%` so VoiceOver's focus rectangle covers the entire card rather than a 1px dot. `pointer-events: none` prevents the invisible span from intercepting clicks. `section { position: relative }` was added to `style-flight.scss` to contain the absolute-positioned span.

**Hiding the visual timeline** — `auro-flightline` is set to `aria-hidden="true"` on the light DOM host element in `firstUpdated()`. A `MutationObserver` covers dynamically added flightlines. `disconnectedCallback` tears down the observer.

**Removed** — `composeScreenReaderSummary()`, `composeScreenReaderHeader()`, and all `util_displayHiddenVisually` hidden divs from `auro-flight-main` and `auro-flight-header`. Sub-components render visual content only.

**i18n** — 15 `i18n-*` string props with English defaults in the constructor. An `ariaLabel` prop overrides the entire computed label. `readStation()` and `convertTime()` extracted to `util/util.js` with undefined guards. New `util/i18n.js` exports `interpolate()`.

**`auro-datetime` v5 migration** — `type="tzTime" setDate=` → `type="time" value=` in `src/auro-flight-main.js`. `datetimeVersion.js` bumped to `5.0.0`.

---

## Why This Works

**`&#8203;` + `role="text"` + `aria-label` solves three VoiceOver problems at once.**
- The zero-width space satisfies Safari's requirement that an element have non-empty content — without it, VoiceOver skips the element entirely on swipe.
- `role="text"` (a WebKit extension) makes VoiceOver use the `aria-label` value as the accessible name rather than reading the DOM text content — this prevents punctuation from being announced as "full stop."
- `aria-label` provides the full flight announcement as a clean string.

**Setting `aria-hidden` on the light DOM element works cross-browser.** `aria-hidden="true"` on `<auro-flightline>` itself (not a shadow DOM ancestor's slot container) reliably hides the element and all its children from every AT's accessibility tree.

**`auro-datetime` v5 uses wall-clock time by default.** The new `type="time"` with `value=` renders the time from the ISO 8601 offset, which is what the flight display requires. The old `type="tzTime" setDate=` API was removed in v5.

**`stops=[]` edge case.** Changed `else if (!this.stops)` to `else` so empty arrays correctly fall through to the nonstop branch.

---

## Outcome

Flight cards now announce a complete, coherent sentence to screen reader users on card entry — including on iPhone via VoiceOver swipe. The announcement covers everything needed to identify and choose a flight without navigating inside the card. Departure and arrival times display correctly after the `auro-datetime` v5 migration. Airlines and partners can localize the announcement into any language using HTML attributes alone.

## Learnings

- `aria-hidden` set on a shadow DOM ancestor does not reliably hide slotted light DOM children. Set it on the slotted element itself.
- iOS VoiceOver skips shadow DOM elements with no accessible text node, even if they have `aria-label`. A `&#8203;` (zero-width space) text node is sufficient to prevent skipping.
- `role="text"` (WebKit extension) makes VoiceOver read `aria-label` instead of text content, preventing punctuation from being announced as "full stop."
- `aria-label` alone on a `<span>` without a role is ignored by VoiceOver — the element needs a role that supports accessible naming.
- VoiceOver's focus rectangle wraps the element's rendered dimensions. A `100% × 100%` absolutely-positioned visually-hidden span gives users a full-card focus highlight. Add `pointer-events: none` to prevent click interception.
- Two SR content sources (short `aria-label` + detailed hidden div) create double-read risk on some AT. One complete `aria-label` is preferable when the content fits.
- Guard utility functions against `undefined` input — web component props are often `undefined` before the first render cycle.
- `stops=[]` is truthy — `else if (!this.stops)` is not the same as "no stops." Use `else` or check `.length`.
- MutationObserver in `firstUpdated` + `disconnectedCallback` teardown is the correct pattern for watching light DOM mutations in LitElement.
- Dependency version pinning files (`datetimeVersion.js`) must be updated in sync with `package.json` upgrades — a version mismatch causes silent API regression.

## Iterations That Didn't Work

- **Short `aria-label` + `util_displayHiddenVisually` dual approach.** Kept hidden divs for detailed navigation, added only a short card-entry label. TRD testing showed hidden divs are inconsistent across AT, and NVDA browse mode double-reads. Abandoned for single complete label.
- **`aria-label` directly on shadow `<section>`.** Initial implementation. VoiceOver iOS skipped the card because all shadow DOM children were `aria-hidden` — VoiceOver found no text node to anchor to and moved past the element.
- **`aria-label` + `role="group"` on host element.** Moved the label to the `auro-flight` host in `updated()`. Axe accessibility check failed: `aria-label` is not permitted on elements with the default `generic` role.
- **`role="article"` on host element.** Changed host role to `article`. Axe passed, but VoiceOver iOS still skipped the card — `role="article"` with all `aria-hidden` children produces no text node for VoiceOver to stop at.
- **`<span>` with text content + `<section aria-label>`.** Span inside section provided the text node; section `aria-label` provided the announcement. VoiceOver read the label twice — once as the region name on entry, once when navigating to the span inside. Removed section `aria-label`, kept span text content only.
- **Span with text content (no `aria-label`).** VoiceOver read the span text character by character and announced punctuation as "full stop." Replaced text content with `&#8203;` and moved the label to `aria-label` on the span with `role="text"`.
- **`canceled` boolean prop on `auro-flight`.** Planned top-level flag forwarded to sub-components. Abandoned — cancellation is already expressed via `stops[].canceled` and `flightline[canceled]`; a separate boolean would require consumers to keep two sources in sync.
- **i18n JSON forwarding to child components.** Planned to serialize a resolved i18n object and pass it down. Unnecessary once all SR content moved to `auro-flight._buildAriaLabel()`; sub-components have no SR output.
- **`else if (!this.stops)` for nonstop detection.** Silent bug: `stops=[]` fell through all branches with no text appended. Fixed by using plain `else`.
- **One-time `aria-hidden` in `firstUpdated`.** Only covered the flightline present at first render. Fixed by adding a `MutationObserver`.
