# AB#1499242

## Executive Summary

This change makes flight cards in the Alaska Airlines design system fully readable by screen readers. Previously, users relying on VoiceOver, TalkBack, NVDA, or JAWS could reach a flight card but heard it broken into disconnected fragments with no coherent summary. Now the card announces a single, complete sentence on entry covering flight number, route, times, stops, reroutes, cancellation, and duration. Airlines and partners can localize this announcement using `i18n-*` HTML attributes without changing any JavaScript. Code review iterations also fixed several edge cases: UTC timestamp handling, observer reconnection on DOM moves, exact-hour duration formatting, a flight-number spacing bug, null-safety for the `flights` prop, a documentation gap around the `aria-label` consumer override, and a silent accessibility regression where an empty `aria-label=""` would have muted the announcement entirely.

## The Problem

Customers who are blind or have low vision use screen readers to navigate flight listings. The `auro-flight` card gave screen readers no structured entry point — the reader traversed each visual element individually with no sentence framing any of it. Users had no way to quickly identify a flight without navigating inside the card element by element.

Secondary issues discovered during development and code review:
- iOS VoiceOver's swipe-right navigation skipped `auro-flight` cards entirely.
- `auro-datetime` v5 changed its API, causing departure and arrival times to display as dates instead of times.
- UTC Z-suffix ISO 8601 timestamps produced `"Invalid Date"` in the screen reader announcement.
- Dynamic `aria-label` changes on the host element were not reflected in the announcement until the next unrelated render.
- Flight numbers with embedded spaces (e.g. `"AS 1436"`) produced triple-spaces when letter-spaced.
- `convertDuration(undefined)` passed `"NaNh "` to both the sr-label and the visual header.
- All three MutationObservers were set up in `firstUpdated()` and not reconnected if the element was moved in the DOM.
- `flights=null` caused a TypeError in both `_buildAriaLabel()` and `auro-flight-header.flightType()` — React consumers commonly pass `flights={null}` while data is loading, which Lit does not treat as the default `[]`.
- Documentation for the `aria-label` consumer override used the camelCase name `ariaLabel` instead of the correct HTML attribute name `aria-label`, causing consumers to call `setAttribute("ariaLabel", …)` which the MutationObserver silently ignores. The docs also did not mention that the element removes `aria-label` from the host after consuming it, surprising consumers who checked `el.hasAttribute("aria-label")`.
- Setting `aria-label=""` (empty string) on the host element silently produced `aria-label=""` on the sr-label span, making the flight card completely silent to screen readers without any error. A consumer who sets `el.setAttribute("aria-label", "")` to try to clear a previous override would unknowingly mute AT for all users of that card.

## Root Cause

**1. No coherent SR entry point.** `<section part="flightContainer">` had no `aria-label`. Screen readers entered and read visual children individually.

**2. Shadow DOM `aria-hidden` leakage.** `aria-hidden="true"` on the shadow DOM slot container does not reliably hide slotted light DOM children across all browsers and AT.

**3. iOS VoiceOver requires a concrete text node.** An `aria-label` attribute alone on a shadow DOM element is insufficient — VoiceOver skips elements with no accessible text node when all shadow children are `aria-hidden`.

**4. `auro-datetime` v5 API change.** `setDate` → `value`, `type="tzTime"` → `type="time"`. Version pin in `datetimeVersion.js` was not updated.

**5. `convertTime` and `getDateDifference` assumed fixed-length offsets.** `time.slice(0, -6)` stripped a 6-char `±HH:MM` offset but produced `"Invalid Date"` for 1-char `Z` suffix. `slice(0, -15)` in `getDateDifference` had the same problem.

**6. `transportAttributes` does not trigger Lit re-renders.** The `transportAttributes` library function moves attribute values between DOM elements synchronously but never calls `requestUpdate()`. A dynamic `el.setAttribute("aria-label", …)` after first render left the sr-label span stale until another property change happened to trigger a re-render.

**7. Observers set up in `firstUpdated` don't survive DOM moves.** `firstUpdated` runs once. Disconnecting the element then reconnecting it left all three MutationObservers dead.

**8. Flight number letter-spacing triple-space.** `Array.from("AS 1436").join(" ")` included the space character in the join, producing `"A S   1 4 3 6"` (triple space at the original space position). Screen readers handle this inconsistently.

**9. `_buildAriaLabel()` called `this.flights.length` without a null guard.** The constructor sets `this.flights = []`, but a consumer passing `flights={null}` (standard React pattern for "not yet loaded") overwrites that default. Lit does not restore it. `this.flights.length` then throws `TypeError: Cannot read properties of null`.

**10. `auro-flight-header.flightType()` called `this.flights.length` without a null guard.** Same bug in the sub-component: `flights` is passed as `JSON.stringify(this.flights)` from `render()`, which serializes `null` as the string `"null"`. `JSON.parse("null")` produces `null`, so `this.flights.length` in the header also throws.

**11. Documentation used the camelCase attribute name.** `docs/partials/api.md` referred to the "ariaLabel attribute" and told consumers to use `setAttribute("ariaLabel", …)`. The MutationObserver in `connectedCallback` watches `attributeFilter: ["aria-label"]` (kebab-case). A consumer following the docs would set the wrong attribute and see no effect. Additionally, the docs did not state that the element removes `aria-label` from the host after consuming it — consumers who checked `el.hasAttribute("aria-label")` after setting it would get `false` with no explanation.

**12. `_consumeAriaLabel()` stored empty string as the override.** `hasAttribute("aria-label")` returns `true` even when the value is `""`. The original code stored `this.getAttribute("aria-label")` directly into `_ariaLabelOverride`. The render binding `this._ariaLabelOverride ?? this._buildAriaLabel()` uses nullish coalescing — `""` is not `null` or `undefined`, so `?? ` never fell back to the computed label. The result was `aria-label=""` on the sr-label span, which silences AT without any error or console warning. A consumer attempting to clear a previous override via `el.setAttribute("aria-label", "")` would unknowingly break accessibility for all users of that card.

## The Fix

**Screen reader announcement** — A visually-hidden `<span role="text" class="sr-label" aria-label="${label}">&#8203;</span>` is the first child of the shadow DOM `<section>`. `_buildAriaLabel()` assembles the full announcement from flight number, departure, arrival, day diff, stops/layovers, reroutes, nonstop/canceled, and duration.

**VoiceOver anchor** — `&#8203;` (zero-width space) satisfies Safari's non-empty text requirement without producing spoken output. `role="text"` (WebKit extension) forces VoiceOver to read `aria-label` rather than text content, preventing punctuation from being announced as "full stop." `.sr-label` is sized `100% × 100%` so VoiceOver's focus rectangle covers the full card; `pointer-events: none` prevents click interception.

**`aria-label` consumer override** — Mapped to the standard `aria-label` HTML attribute. A `_consumeAriaLabel()` method watches the host with a MutationObserver, reads and removes `aria-label` when set, and stores it in `_ariaLabelOverride` reactive Lit state — which triggers an automatic re-render. Empty string is explicitly treated the same as absence (`value || null`), so `aria-label=""` falls back to the computed label rather than silencing the screen reader. This replaces the earlier `transportAttributes` approach that didn't call `requestUpdate()`.

**Hiding the visual timeline** — `auro-flightline` receives `aria-hidden="true"` on the light DOM host in `connectedCallback()`. A `MutationObserver` on the host (`childList`) applies it to dynamically added flightlines. A separate `MutationObserver` on the flightline itself watches the `canceled` attribute and calls `requestUpdate()` on change.

**Observer lifecycle** — All three observers (`_flightlineObserver`, `_flightlineAttrObserver`, `_ariaLabelObserver`) are now set up in `connectedCallback()` and torn down in `disconnectedCallback()`. `firstUpdated()` handles only shadow DOM setup (`exposeCssParts`, footer slot). This ensures observers survive element moves in the DOM.

**i18n** — 15 `i18n-*` string props. Defaults stored in `_I18N_DEFAULTS` module-level const; `Object.assign(this, _I18N_DEFAULTS)` in the constructor sets initial values. Each property has an inlined descriptor with `attribute: "i18n-..."` (for static doc generation) and `_i18nConverter(key)` (restores English default on attribute removal or clear). `@default` JSDoc tags on each property ensure the doc generator preserves defaults in the generated API table.

**Utility fixes** — `convertTime` strips the offset with a regex (`/([+-]\d{2}:\d{2}|Z)$/`) instead of fixed-length slicing, then validates with `isNaN`. `getDateDifference` uses `slice(0, 10)` (date-only prefix) for all ISO 8601 formats. `convertDuration` returns `hours` alone (no trailing space) when minutes is zero.

**Flight number spacing** — `Array.from(flights[0]).filter(c => c !== " ").join(" ")` removes the embedded space before joining, producing `"A S 1 4 3 6"` instead of `"A S   1 4 3 6"`.

**Visual header guard** — The same duration validity check applied in `_buildAriaLabel()` is now also applied to the `duration` binding on `<auro-flight-header>` in `render()`, preventing `"NaNh "` from appearing in the visual display.

**`auro-datetime` v5 migration** — `type="tzTime" setDate=` → `type="time" value=`. `datetimeVersion.js` bumped to `5.0.0`.

**`flights=null` null guards** — `_buildAriaLabel()` uses `const flights = this.flights ?? []`, so a `null` value is safely treated as an empty-flight list rather than throwing. `auro-flight-header.flightType()` uses `(this.flights ?? []).length`. The `render()` binding uses `JSON.stringify(this.flights ?? [])` so the header never receives `"null"` as its `flights` attribute.

**Documentation fix** — `docs/partials/api.md` now uses `aria-label` (kebab-case) consistently throughout the consumer override section. A new note explains that after the element processes `aria-label`, the attribute is removed from the host — `el.hasAttribute("aria-label")` returns `false`. This is now documented as expected behavior. Removed phantom placeholders (`{flightNumber}`, `{departureTime}`, `{arrivalTime}`) — they were documented but never substituted by `_buildAriaLabel()`.

## Why This Works

**`&#8203;` + `role="text"` + `aria-label`** — the zero-width space prevents VoiceOver from skipping, `role="text"` prevents punctuation pronunciation, and `aria-label` delivers the clean announcement string.

**Light DOM `aria-hidden`** — setting on the slotted host element (not a shadow DOM ancestor) reliably hides all descendants in every AT implementation.

**Reactive Lit state for aria-label override** — `_ariaLabelOverride: { state: true }` is a Lit internal reactive property. Any assignment to it schedules a re-render automatically, solving the stale-span problem that `transportAttributes` had.

**`connectedCallback` for observer setup** — Lit's `connectedCallback` fires on every DOM connection (initial and reconnect), making it the correct lifecycle hook for observers that must survive element moves. `firstUpdated` fires only once.

**`slice(0, 10)` for date difference** — `"2022-05-04"` is always the first 10 characters of any ISO 8601 datetime, regardless of the offset format (`-07:00`, `+00:00`, `Z`).

**Static-analysis-friendly property definitions** — inlining `attribute: "i18n-departure"` directly in each property descriptor (rather than returning it from a factory function) lets the doc generator read and use the actual HTML attribute name.

**`?? []` for null-safe arrays** — nullish coalescing treats only `null` and `undefined` as absent, preserving an intentionally empty array `[]` as a valid "no flights" state. Using `|| []` would also replace `[]` with `[]` but would incorrectly treat `0` or `""` as absent, so `??` is the correct operator here.

**`|| null` for the empty-string aria-label guard** — `""` is not `null` or `undefined`, so `?? null` would not catch it. Using `value || null` converts any falsy value (including empty string) to `null`. Since `null` is the sentinel value meaning "no override" and `""` has no valid semantic as an `aria-label` value (it would silence AT), treating them identically is correct. The fallback to `_buildAriaLabel()` is always safe and preferred over a silent accessibility failure.

## Outcome

Flight cards announce a complete, coherent sentence to every screen reader on every platform tested. iPhone VoiceOver swipe navigation reaches cards correctly. The announcement stays current when cancellation state or the consumer's `aria-label` override changes dynamically. Departure and arrival times display correctly. Edge cases in the time utilities, duration formatting, flight number spacing, null-safety for the `flights` prop, and the empty-string `aria-label` guard are resolved. Documentation for the `aria-label` consumer override now correctly names the HTML attribute, explains the removal-after-consumption behavior, and is protected against silent AT muting from accidental empty-string usage. 67 unit tests cover all paths.

## Learnings

- `aria-hidden` on a shadow DOM ancestor does not reliably hide slotted light DOM children. Set it on the slotted element itself.
- iOS VoiceOver skips shadow DOM elements with no accessible text node. `&#8203;` (zero-width space) is sufficient to prevent skipping.
- `role="text"` (WebKit) makes VoiceOver read `aria-label` instead of text content, preventing punctuation from being announced as "full stop."
- `role="text"` is only valid on `<span>` and similar generic elements — not on `<label>`, which has its own ARIA role semantics.
- VoiceOver's focus rectangle matches the element's rendered dimensions. Size the sr-label span `100% × 100%` for a full-card focus highlight; add `pointer-events: none` to prevent click interception.
- `transportAttributes` from auro-library moves attribute values but does not call Lit's `requestUpdate()`. Use reactive state + MutationObserver instead when a re-render is needed on attribute change.
- MutationObservers set up in `firstUpdated()` do not survive element disconnect/reconnect. Use `connectedCallback` for setup and `disconnectedCallback` for teardown.
- `Array.from(str).join(" ")` includes every character, including embedded spaces. Filter them out before joining to avoid triple-spaces in letter-spaced output.
- `convertTime(time.slice(0, -6))` breaks for Z-suffix ISO 8601 strings. Strip the offset with a regex instead of a fixed-length slice.
- `else if (!this.stops)` is not the same as "no stops." Use `else` or check `.length` — empty arrays are truthy.
- Static doc generators can't evaluate factory functions returning property descriptors. Inline the `attribute: "..."` field directly so the generator reads it.
- `@default` JSDoc tags are required for the doc generator to preserve defaults in the generated API table when defaults come from `Object.assign` rather than literal initializers.
- Document only the placeholder keys that `interpolate()` actually receives — phantom placeholders in docs cause consumer templates to silently produce literal `{key}` text.
- Dependency version pin files must be updated in sync with `package.json` upgrades to avoid silent API regressions.
- `convertDuration` returning `` `${hours} ${minsString}` `` with empty `minsString` produces a trailing space. Return `hours` alone when `minsString` is empty.
- React commonly passes `null` for "not yet loaded" props. Constructor defaults like `this.flights = []` are overwritten when a consumer explicitly passes `null`. Always guard array props at the point of use with `?? []`, not just at initialization.
- Setting a Lit constructor default does not prevent a consumer from passing `null` — Lit reflects incoming property values directly. For array props that must never be null at runtime, guard every `.length` access with `?? []`.
- If an element removes an HTML attribute after consuming it (as `_consumeAriaLabel()` does with `aria-label`), document this explicitly. Consumers who check `el.hasAttribute("aria-label")` after setting it will see `false` — without documentation this looks like a bug.
- Use kebab-case attribute names consistently in documentation. Documenting `ariaLabel` (camelCase) when the actual HTML attribute is `aria-label` (kebab-case) causes consumers to use `setAttribute("ariaLabel", …)`, which silently fails when the observer filters on `"aria-label"`.
- `hasAttribute("aria-label")` returns `true` even when the attribute value is `""`. When consuming an `aria-label` attribute as an override, guard against empty string with `|| null` (not `?? null`). Storing `""` in a reactive property and using nullish coalescing in render will produce `aria-label=""` on the target element, silencing AT with no error or warning. An empty `aria-label` has no valid semantic — the correct fallback is always the computed label.

## Iterations That Didn't Work

- **Short `aria-label` + `util_displayHiddenVisually` dual approach.** Double-read risk on NVDA; hidden divs inconsistent across AT. Abandoned for a single complete label.
- **`aria-label` directly on shadow `<section>`.** VoiceOver skipped the card — no text node for VoiceOver to anchor to when all children are `aria-hidden`.
- **`aria-label` + `role="group"` on host element.** Axe flagged `aria-label` on `generic` role as prohibited.
- **`role="article"` on host element.** Axe passed; VoiceOver still skipped — no accessible text node inside the article.
- **`<section aria-label>` + `<span>` with text content.** VoiceOver double-read: once as the region name on entry, once when navigating to the span.
- **`<span>` with text content, no `aria-label`.** VoiceOver announced punctuation as "full stop." Fixed by replacing text content with `&#8203;` and moving the announcement to `aria-label` with `role="text"`.
- **`<label role="text">`.** Axe flagged `aria-allowed-role` violation — `role="text"` is not permitted on `<label>`. Reverted to `<span role="text">`.
- **`transportAttributes` for aria-label override.** Moved attribute from host to sr-label span correctly but never called `requestUpdate()`, leaving the span stale after dynamic changes. Replaced with `_consumeAriaLabel()` + `_ariaLabelOverride` reactive state.
- **`_i18nProp` factory helper.** Clean DRY pattern but static doc generators can't evaluate the function call to find the `attribute:` field, causing generated docs to show camelCase property names instead of kebab-case attribute names. Replaced with inlined descriptors + `_i18nConverter` factory (converter only, not the full descriptor).
- **Observer setup in `firstUpdated`.** Only ran once — observers stayed dead after element disconnect/reconnect. Moved to `connectedCallback`.
- **`canceled` boolean prop on `auro-flight`.** Planned top-level flag. Unnecessary — cancellation is expressed via `stops[].canceled` and `flightline[canceled]` already.
- **i18n JSON forwarding to child components.** Unnecessary once all SR content consolidated in `_buildAriaLabel()`.
- **`else if (!this.stops)` for nonstop detection.** Silent failure for `stops=[]`. Fixed with plain `else`.
- **Storing `aria-label` value unconditionally in `_consumeAriaLabel()`.** `getAttribute("aria-label")` returns `""` for an empty attribute, which nullish coalescing (`??`) passes through unchanged, producing `aria-label=""` on the sr-label span and silencing AT. Fixed with `value || null` to treat empty string as absent.
